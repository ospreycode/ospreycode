# `session-store`：session 记录

保存 session 的事件、会话树和检查点索引，供恢复、回退、分叉、评测和审计使用。本包只负责存取和检查范围，不理解事件的内容：各类事件的内容由产生它的包定义（见 overview 的[依赖方向](../overview.md#依赖方向)）。它只在 Host 一侧使用，runtime 经通道读写（见 agent-runtime 的[通道](agent-runtime.md#通道)）。

和长期记忆（见 [memory](memory.md)）分成两个包：session 记录从 P1 起就是恢复、评测和审计的基础，要求只追加、原样重放；长期记忆 P3 才做，做法还会更换，评测还要有去掉记忆代码的无记忆组。

## 模块

```text
session-store/
  events/       事件的公共字段、格式版本和迁移
  tree/         会话树：run 的接续关系、当前位置、回退和分叉
  checkpoints/  检查点索引：每次用户输入对应的 run 和序号范围、快照的引用、改动的路径
  blobs/        按引用保存的大内容，如完整上下文、超长的工具输出
  storage/      本地存储和索引（实现可替换），以及导出、删除和重建
  sdk/          对外接口：追加、按路径读取、查询、移动当前位置、分叉、按事件脱敏、导出、删除
```

## 要点

- 保存完整的原始事件，消息按 `api` 的内部协议保存，格式迁移由定义格式的包提供（见 api 的[内部协议](api.md#内部协议)）；摘要和向量检索不能代替恢复所需的原始记录。
- Host 的模型代理另存每条消息在目标协议里的原文，作为 agent-host 定义的事件，键为 `message_id`、内部消息的内容哈希、协议、服务和 API 版本（见 api 的[原样重放](api.md#原样重放)）。
- 只追加，唯一的例外是下文的按事件脱敏。同一个 session 同时只有一个写入者：写入前取得跨进程的写锁，第二个 Host 打开同一个 session 时报错（见 agent-host 的 [session 的打开和关闭](agent-host.md#session-的打开和关闭)）；不同的 session 可以由多个 Host 进程同时写入。
- 按 user 和 project 分开存储，读、写、删都检查范围，不能只在查询时按附加字段过滤。project 由 Host 判断（见 agent-host 的[项目身份](agent-host.md#项目身份)）。
- 工具输出会带出敏感内容：存储文件只对当前用户可读，导出前用调用方传入的检测函数做密钥检测（Host 的 `redaction/`，见 agent-host 的[模块](agent-host.md#模块)）。
- 用户可以删除整个 session，记录也有保存期限（见下文[保存期限](#保存期限)）。彻底删除要覆盖原始事件、索引、大内容，以及本项目产生的备份和导出；重建索引时不能把已删除的内容找回来。以被删 session 为来源的长期记忆由 Host 协调 memory 一起处理（见 memory 的[要点](memory.md#要点)）。
- 按事件脱敏：用户要求忘记某条内容时，用占位内容覆盖该事件的内容和它引用的大内容，并追加一条脱敏事件。大内容还被其他 session（如分叉）引用时，先告诉用户会影响几个 session，确认后一起脱敏。这是对历史的一次改写，该 session 之后的推理内容在恢复时作废（见 api 的[转换规则](api.md#转换规则)）。
- 不内置默认的存储位置，所有位置都由调用方显式传入，并通过重启测试。

## 存储格式

用 SQLite，每个项目一个数据库文件 `data/projects/<project_id>/sessions.sqlite`（见 agent-host 的[目录位置](agent-host.md#目录位置)），事件、索引和按引用保存的大内容都放在里面；大内容按 SHA-256 只存一份，并记录引用它的 session。检查点的文件快照放在影子仓库里，不放在这里（见 agent-host 的[快照和撤销](agent-host.md#快照和撤销)）。

- 按项目分库落实"按 user 和 project 分开存储"：不同项目的 Host 进程互不争锁，删除整个项目时直接删文件。CLI 的会话列表默认只列出当前项目的 session，`--all` 跨项目逐个打开数据库。
- 用 Node 内置的 `node:sqlite`，不增加依赖：它从 24.15.0 和 25.7.0 起标为 Release candidate、不再输出实验性警告，WAL、`timeout`、`backup()`、自定义函数、FTS5 和 session 扩展都可用，这也是 Node 最低版本定为 24.15.0 的原因之一（见 overview 的[语言和运行环境](../overview.md#语言和运行环境)）；better-sqlite3 只在要支持 Node 22 时才有必要。
- 连接用 WAL、`timeout: 5000`（5 秒，照 Codex rust-v0.167.0）打开，显式设 `synchronous=FULL`；写事务一律用 `BEGIN IMMEDIATE`，并保留每个 session 一个写入者的锁。接口是同步的，等锁时阻塞 Host，所以事务要短。
- 为满足彻底删除，每个连接设 `PRAGMA secure_delete=ON`，用到 FTS5 时开启它的 `secure-delete` 并在删除后执行 `optimize`，删除后执行 `PRAGMA wal_checkpoint(TRUNCATE)`：实测之后主库和 WAL 里都找不到被删的内容，不开这两个开关则要 `VACUUM`。
- WAL 依赖共享内存，数据目录在网络文件系统上时启动直接报错，不照 Codex 改用 DELETE 模式。
- 大内容也放在库里，不分"小的进库、大的放文件"两种存法；大内容普遍超过 1 MiB 或库超过数 GB 时再移到文件里，作为一次格式迁移。
- 迁移：格式版本记在 `PRAGMA user_version`。Host 打开时版本较旧，先用 `backup()` 在同一目录做一份备份，再在一个事务里按顺序执行迁移，成功后删除备份；版本比程序新时报错，不打开（见 overview 的[版本号](../overview.md#版本号)）。
- 导出：一个 session 一个 JSONL 文件，第一行是元数据和格式版本，之后每行一个事件，大内容以 base64 内嵌，分叉连带导出它引用的父 session 前缀；导出前做密钥检测（见上文[要点](#要点)），导出的文件由用户自己保管，不在清理范围内。
- 重建：会话树、检查点索引和全文索引都能从事件表重建；删除时事件一起删除，所以重建找不回已删除的内容。
- session 的删除、导出和索引重建是 P3 的内置命令 `ospreycode session delete|export|rebuild`。

## 保存期限

session 默认保存 30 天，从最后一次写入事件算起，照 Claude Code 2.1.318 的 `cleanupPeriodDays`。

- 期限只能在用户级配置里设，单位为天，最小为 1，不提供 0 或"永久"这类特殊值，需要长期保存时设一个大数；仓库配置和启动参数都不能改它，否则一个仓库就能让用户的历史一天就被删掉。
- 清理在 Host 启动后于后台进行，只由拿到数据目录清理锁的 Host 执行，跳过任何 Host 正打开或持有写锁的 session，以及 24 小时内写过的 session。
- 到期按彻底删除处理：事件、索引、只被它引用的大内容和检查点引用一起删除，随后按下文[检查点的保留](#检查点的保留)里的分工清理影子仓库。一个项目的 session 都被删除后，这个项目的构建缓存也一起删除（见 sandbox 的[构建工具的缓存](sandbox.md#构建工具的缓存)）。
- 到期不删除从该 session 得到的长期记忆，只把来源标为已过期：到期只是存储管理，用户并没有表示不要这些内容。用户主动删除 session 时，只来自它的记忆一起彻底删除，由 Host 协调。

## 事件格式

本包规定事件的公共字段和存储格式，各类事件的内容由产生它的包定义。

- 每个事件都带 `event_id`、run 内递增的序号、时间、来源、关联标识、类型和格式版本。来源和关联标识由 Host 按通道核实后写入，不采信沙盒内填写的值。
- 模型用量和费用、工具耗时、memory 检索到了什么、context 最终选用了什么，都作为事件记录，evaluation 靠它们判断问题出在哪一步。完整上下文、长输出这类大内容按引用保存，不在每个事件里重复。
- 存储格式不对外：CLI 的 JSON 事件流用 agent-host 定义的对外事件格式（见 agent-host 的[对外的事件格式](agent-host.md#对外的事件格式)），hooks 的输入也由 agent-host 定义（见 agent-host 的 [Hooks](agent-host.md#hooks)），两者各有版本，存储格式迁移不会让用户的脚本和 hooks 失效；只用于实时显示的流式增量不存储。

## 会话的分支和回退

照 pi、Codex 和 Claude Code 共同的做法：

- **历史从不删除。** 会话是一棵树，当前对话是从根到"当前位置"的一条路径。回退把当前位置移到某次用户输入之前，新的输入接在那里，被放弃的那一段仍然保留，可以再切回去；分叉从某个位置开出一个新的 session，记下来源 session 和位置。
- **分支点是用户输入的边界**：每次用户输入有稳定的标识和自己的检查点，task 中途插入的 steering 也是，可以回退到它之前；只有正在运行的 task 不能作为分支点。
- **发给模型的只有这条路径上的历史**：路径上最近一次压缩之后的内容，加上新追加的内容；之前的内容没有改写，提示缓存和 Anthropic 的推理内容校验都不受影响。被放弃的那一段可以选择生成摘要，作为一条 user 消息追加（照 pi，要多调用一次模型），默认不生成。
- **当前位置显式保存**，回退立即写入，否则在下一次输入前退出，回退就丢了。
- **设置**：模型和推理强度按路径上的记录（照 pi）；沙盒模式和审批策略保持当前的值，不因为回退到较早的位置而放宽，因为历史记录不能产生新的授权（见 overview 的[所有包都遵守的规则](../overview.md#所有包都遵守的规则)）；和当前设置不同的部分作为追加的变更加在回退点之后。
- **文件和对话分开还原**：回退对话不改文件；文件按检查点还原，用户可以只还原对话、只还原代码或两者都还原（照 Claude Code）。快照在每次工具调用之前由 Host 做（见 agent-host 的[快照和撤销](agent-host.md#快照和撤销)），所以 shell 命令造成的改动也能还原，冲突检查沿用那里的规则；检查点保留多少个、保留多久，见下文[检查点的保留](#检查点的保留)。
- **回退之后要重新计算的状态**：文件读取的新鲜度记录、已加载的 skills。

为此，事件格式要能表示：每个 run 记下它接在哪个 run 的哪个序号之后（`base = {run_id, seq}`），恢复、回退和分叉都是"从某个位置开始一个新的 run"；session 记下当前位置，以及回退时被放弃的位置；从用户输入（task 和 steering）到它所在的 run 和序号范围的索引；每次用户输入一个检查点事件，关联这次输入之后第一次工具调用之前的快照，以及之后改动的路径（包括新建的文件，还原时要删除它们）。

## 分叉的存储

分叉引用父 session，不复制：只记录父 session 和截止的事件，之后只写自己的事件；大内容按内容哈希只存一份，记录引用它的 session；检查点的快照本来就在项目的影子仓库里，分叉只为沿用的检查点建自己的引用，不复制任何文件内容。整份复制的分叉在 Codex 出现过 400 GiB 的占用。

- 父 session 被删除或到期时，先在同一个事务里把分叉仍引用的事件和大内容改记到分叉名下，再删除其余内容，影子仓库里的引用随之转移，之后清理不再被引用的对象；每个项目一个数据库文件（见上文[存储格式](#存储格式)），所以这能在一个事务里完成，不会删到一半。多层分叉时从最深的分叉开始逐层改记。
- 不照 Codex 拒绝删除仍被分叉引用的 session：分叉是另外的 session，拒绝删除会让彻底删除取决于用户先处理分叉。删除前告诉用户还有几个分叉包含这段内容，用户可以选择一起删除。

## 回退时的后台命令

回退开始新的 run，但后台命令属于 session（见 agent-runtime 的[后台命令](agent-runtime.md#后台命令)）。回退到某个检查点时，结束在这个检查点之后启动的后台命令，保留之前启动的，按命令的启动事件在会话树里的位置判断。

- 之后启动的命令属于被放弃的分支，继续运行会把输出送进不认识它们的对话，还可能在还原代码后继续改文件、破坏撤销的结果；之前启动的命令（如开发服务器、监视进程）仍在保留的历史里，全部结束会让历史和实际状态不一致，它们之后的输出照常送到当前分支。
- 待批准的请求一律取消：它们属于被中止的 run，新的 run 需要时重新请求。
- 只回退对话时也按同样的规则结束命令，规则不随选项变化；同时还原代码时，先结束命令再还原，仍有保留的命令在运行时，还原前提示它们可能继续改动文件。

## 检查点的保留

每个 session 保留最近 100 个检查点的快照，照 Claude Code。

- 更早的检查点仍留在会话记录里，可以回退对话，但标为"快照已清理"，不能还原代码。检查点内按工具调用做的快照跟随所属检查点一起清理，不单独计数。
- 快照的保存期限跟随 session，不单独设置：session 不在了快照就没有用处，快照先过期又会多出一种"能回退对话、不能还原代码"的状态。检查点数量也不提供配置项。
- 每个检查点在影子仓库里各有一个引用，不串成一条提交链，删除旧检查点只要删掉它的引用；设 `core.logAllRefUpdates=false`，避免 reflog 留住对象。清理的分工：session-store 只返回不再被任何 session 引用的检查点引用名，Host 的 `workspace/` 在快照沙盒里删除引用并运行 `gc`，`gc` 只回收不再被引用的对象。不照 opencode 不建引用、每小时 `git gc --prune=7.days`：仍被 session 用到的快照也会被清掉。
