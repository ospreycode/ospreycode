# `session-store`：session 记录

保存 session 的事件、会话树和检查点索引，供恢复、回退、分叉、评测和审计使用。本包只负责存取和检查范围，不理解事件的内容：各类事件的内容由产生它的包定义（见 overview 的[依赖方向](../overview.md#依赖方向)）。它只在 Host 一侧使用，runtime 经通道读取（见 agent-runtime 的[通道](agent-runtime.md#通道)）。

和长期记忆（见 [memory](memory.md)）分成两个包：session 记录从 P1 起就是恢复、评测和审计的基础，要求只追加、原样重放；长期记忆 P3 才做，做法还会更换，评测还要有去掉记忆代码的无记忆组。

## 模块

```text
session-store/
  events/       事件的公共字段、格式版本和迁移
  tree/         会话树：run 的接续关系、当前位置、回退和分叉
  checkpoints/  检查点索引：每次用户输入对应的 run 和序号范围、快照的引用、改动的路径
  blobs/        按引用保存的大内容，如完整上下文、超长的工具输出
  storage/      本地存储和索引，以及导出、删除和重建
  sdk/          对外接口：追加、按路径读取、查询、移动当前位置、分叉、按事件脱敏、导出、删除
```

## 要点

- 保存完整的原始事件，消息按 `api` 的内部协议保存，格式迁移由定义格式的包提供；摘要和向量检索不能代替恢复所需的原始记录。Host 的模型代理另存每条消息在目标协议里的原文（见 api 的[原样重放](api.md#原样重放)）。
- 只追加，唯一的例外是下文的按事件脱敏。同一个 session 同时只有一个写入者：写入前取得跨进程的写锁，第二个 Host 打开同一个 session 时报错（锁的做法见 agent-host 的 [session 的打开和关闭](agent-host.md#session-的打开和关闭)，锁由调用方传入，本包不判断进程身份）；不同的 session 可以由多个 Host 进程同时写入。
- 按 project 分开存储，读、写、删都检查范围，不能只在查询时按附加字段过滤。project 由 Host 判断（见 agent-host 的[项目身份](agent-host.md#项目身份)）；一个 Host 根目录只有一个用户。
- 每个 session 记下元数据：创建时的工作区真实路径、创建和最后写入的时间、标题（第一条用户输入的第一行），供会话列表和恢复使用。
- 存储文件只对当前用户可读。导出前用调用方传入的检测函数做密钥检测，命中的替换成占位（Host 的 `redaction/`，见 agent-host 的[模块](agent-host.md#模块)）。
- 用户可以删除整个 session，记录也有保存期限（见[保存期限](#保存期限)）。彻底删除要覆盖原始事件、索引、大内容和本包做的迁移备份；重建索引时不能把已删除的内容找回来。用户导出的文件由用户自己保管，不在删除范围内。以被删 session 为来源的长期记忆由 Host 协调 memory 一起处理。
- **按事件脱敏**：用户要求忘记某条内容时，用占位内容覆盖该事件的内容和它引用的大内容，并追加一条脱敏事件（`event.redacted`，记下被覆盖的事件的位置）。占位内容由调用方给出，本包不理解事件的内容；事件引用了哪些大内容，按事件内容里出现的 SHA-256 摘要判断（见[分叉的存储](#分叉的存储)）。大内容的键不变，脱敏之后再保存同样的字节会把内容存回去：那是用户重新给出的内容。session 的标题取自被覆盖的输入时，调用方在同一次覆盖里把标题也换掉。同一内容的其他副本由 Host 按 `message_id` 和 `tool_call_id` 这些编号找出后一起覆盖（找法、占位的样子和几个 session 之间的先后见 agent-host 的[按事件脱敏](agent-host.md#按事件脱敏)）：目标协议的原文事件、工具调用事件、`output/` 下的输出文件；包含它的压缩摘要也覆盖，这次压缩作废，恢复时从压缩之前的历史重建，超过阈值时在下一次请求前重新压缩。大内容还被其他 session（如分叉）引用时，先告诉用户会影响哪些 session，确认后一起脱敏。这是对历史的一次改写，路径上包含这个事件的所有 session（包括分叉）之后的推理内容在发给模型时作废，这条消息按占位内容重新转换（见 api 的[转换规则](api.md#转换规则)）。
- 不内置默认的存储位置，所有位置都由调用方显式传入，并通过重启测试。

## 存储格式

用 SQLite，每个项目一个数据库文件 `data/projects/<project_id>/sessions.sqlite`（见 agent-host 的[目录位置](agent-host.md#目录位置)），事件、索引和按引用保存的大内容都放在里面；大内容按 SHA-256 只存一份，并记录引用它的 session。检查点的文件快照放在影子仓库里，不放在这里（见 agent-host 的[快照和撤销](agent-host.md#快照和撤销)）。

- 按项目分库：不同项目的 Host 进程互不争锁，删除整个项目时直接删文件。CLI 的会话列表默认只列出当前项目的 session，`--all` 跨项目逐个打开数据库。
- 用 Node 内置的 `node:sqlite`，不增加依赖：WAL、`timeout`、`backup()`、自定义函数和 FTS5 都可用。
- 连接用 WAL、`timeout: 5000` 打开，显式设 `synchronous=FULL`；写事务一律用 `BEGIN IMMEDIATE`。接口是同步的，等锁时阻塞 Host，所以事务要短。
- 为满足彻底删除，每个连接设 `PRAGMA secure_delete=ON`，用到 FTS5 时开启它的 `secure-delete` 并在删除后执行 `optimize`，删除后执行 `PRAGMA wal_checkpoint(TRUNCATE)`：这样主库和 WAL 里都找不到被删的内容，不用 `VACUUM`。
- WAL 依赖共享内存，Host 根目录在网络文件系统上时启动直接报错。
- 大内容也放在库里，不分"小的进库、大的放文件"两种存法；大内容普遍超过 1 MiB 或库超过数 GB 时，作为一次格式迁移移到文件里。
- **迁移**：格式版本记在 `PRAGMA user_version`，现在是 2（第 2 版加了分叉的来源、被放弃的位置和检查点索引）。Host 打开时版本较旧，先用 `VACUUM INTO` 在同一目录做一份备份（`sessions.sqlite.v<旧版本>.bak`，只对当前用户可读写），再在一个事务里按顺序执行迁移，成功后删除备份；版本比程序新时报错，不打开（见 overview 的[版本号](../overview.md#版本号)）。不用 `backup()`：它是异步的，而打开数据库的接口是同步的，`VACUUM INTO` 同样得到一份一致的副本。迁移失败时备份留着，下一次迁移成功或删除 session 时删掉。
- **导出**：一个 session 一个 JSONL 文件，第一行是元数据和格式版本，之后每行一个事件；大内容以 base64 内嵌在第一次引用它的那个事件的一行里（`blobs` 字段，按摘要列出）。分叉先导出它引用的父 session 前缀，再导出自己的事件。调用方传入的检测函数作用在事件内容的每个字符串和能按 UTF-8 解码的大内容上。导出只读，不取写锁：打开着的 session 也能导出。
- **重建**：会话树和检查点索引都能从事件表重建，做法是按写入顺序重放本包定义的事件（见[事件格式](#事件格式)）；删除时事件一起删除，所以重建找不回已删除的内容。重建在一个事务里改写索引，这时不能有别的写入者：Host 先取得项目里每个 session 的写锁，有一个正被打开着就报错。
- session 的删除、导出和索引重建在 P3 交付（`ospreycode session delete|export|rebuild`）。

## 保存期限

session 默认保存 30 天，从最后一次写入事件算起。

- 期限只能在用户级配置的 `session_retention_days` 里设，单位为天，最小为 1，不提供 0 或"永久"这类特殊值，需要长期保存时设一个大数。仓库配置和启动参数都不能改它，否则一个仓库就能让用户的历史一天就被删掉。
- 清理在后台进行，只由拿到数据目录清理锁的 Host 执行，跳过任何 Host 正打开或持有写锁的 session，以及 24 小时内写过的 session。期限最小是 1 天，到期的 session 至少 24 小时没有写过，不另做判断。
- 创建 Host 时不自己开始清理，由调用方调用 SDK 的 `cleanExpiredSessions()`：嵌入 SDK 的程序和评测不会因为创建了 Host 就被删掉记录。CLI 在交互模式和 `exec` 打开 session 之后调用，不等它做完，退出前等它结束；清理出错只在 stderr 上写一条警告，不改变退出码。
- 分叉不随父 session 到期，各按自己最后一次写入的时间算；父 session 到期时照[分叉的存储](#分叉的存储)把分叉仍引用的事件改记到分叉名下。
- 到期按彻底删除处理：事件、索引、只被它引用的大内容和检查点引用一起删除，随后按[检查点的保留](#检查点的保留)里的分工清理影子仓库。Host 另外删掉它的 `tmp/<session>/` 和 `output/<session>/`。一个项目的 session 都被删除后，这个项目的构建缓存也一起删除（见 sandbox 的[构建工具的缓存](sandbox.md#构建工具的缓存)）；和 `cache clear` 一样只删缓存目录里的内容、留下目录本身：这时可能正有一个新的 session 在打开，它的沙盒按路径放开这个目录。
- 到期不删除从该 session 得到的长期记忆，只把记忆的来源标为"来源已删除"：到期只是存储管理，用户并没有表示不要这些内容。用户主动删除 session 时，只来自它的记忆一起彻底删除，由 Host 协调。

## 事件格式

本包规定事件的公共字段和存储格式，各类事件的内容由产生它的包定义。

- 每个事件都带 `event_id`、run 内递增的序号、时间、来源、关联标识、类型和格式版本。来源和关联标识由 Host 按通道核实后写入，不采信沙盒内填写的值。
- 不属于任何 task 的工作（如后台的记忆提取，见 memory 的[写入](memory.md#写入)）也由 Host 分配一个 `run_id`，事件照常带 run 内的序号和 `event_id`，`task_id` 和 `agent_id` 为空；这种 run 不进入会话树的路径，也不能作为 `base`。
- 会话树和检查点索引靠本包自己定义的几种事件维护，本包只读取这几种事件的内容，索引因此能从事件表重建。它们的 `data` 格式版本取写入时的存储格式版本，格式没有变的旧版本照常接受：
  - `run.started`：每个 run 的第一个事件，`data` 是 `RunRecord`，记下这个 run 接在哪个 run 的哪个序号之后（`base = {run_id, seq}`）。重启、恢复、回退和分叉都是"从某个位置开始一个新的 run"。
  - `position.moved`：把 session 的当前位置移到 `to`（回退到第一次输入之前时为空），写在不属于任何 task 的 run 里。原来的当前位置不在通往新位置的路径上时记为被放弃的位置，可以再移回去；属于 task 的事件写入时当前位置照常移到它。
  - `checkpoint.created`：每次用户输入（task 的输入和 steering）一个，紧跟在输入事件之后、写在同一个 run 里，带输入事件的 `event_id`、种类和这次输入之前的位置 `before`（回退到这个检查点就是把当前位置移到 `before`）。从用户输入到它所在的 run 和序号范围的索引由它得到。
  - `checkpoint.snapshot`：这个 session 做的每次快照一条，记在当时最新的检查点名下，带影子仓库里的提交、和上一次快照相比改动的路径（包括新建和删除的文件）、改动的来源（`agent`、`undo`、`external`）。一个检查点的第一条就是"这次输入之后第一次工具调用之前的快照"，之后改动的路径是它后面各条里来源为 `agent` 的路径。Host 怎样用这些记录还原和检测冲突，见 agent-host 的[快照和撤销](agent-host.md#快照和撤销)。
  - `checkpoints.inherited`：分叉的第一个事件，带分叉时父 session 的整个检查点索引（见[分叉的存储](#分叉的存储)）。
  - `event.redacted`：按事件脱敏的记录。
- **同一份内容的副本带共同的编号**：一段内容在几个事件里各存一份时，写这些事件的包让它们带上同一个编号（`message_id`、`tool_call_id`、`input_id`），按事件脱敏靠编号找全副本，不按内容猜。用户提交的输入因此在 `task.started` 里带着放它的那条 user 消息的 `message_id`：编号由 Host 分配，经 `task/start` 交给 runtime 照用；压缩的 task 没有输入，不带。hooks 的输出（`hooks.ran`）和记忆检索的查询（`memory.retrieved`）同样带着所属的工具调用、排队的输入或消息的编号，候选列表（`memory.candidates`）里的每条候选带着它依据的事件的编号。记忆的内容按记忆的编号找：交给模型的每一份都带着它，`sessionsMentioning` 列出自己的事件内容里出现过一段文字的 session，Host 用它只读有这个编号的 session（见 agent-host 的[按事件脱敏](agent-host.md#按事件脱敏)）。
- 模型用量和费用、工具耗时、memory 检索到了什么、context 最终选用了什么，都作为事件记录，evaluation 靠它们判断问题出在哪一步。完整上下文、长输出这类大内容按引用保存，不在每个事件里重复。
- **图片按引用保存**：事件内容里的图片不带字节，只留对大内容的引用，字节存成大内容，同一张图片在一个项目的库里只有一份。一张图片会出现在工具调用的结果、发给模型的消息和这条消息在目标协议里的原文里，各带一份的话记录是图片的三倍多；只存一份，按事件脱敏和删除时也只用处理这一份。本包不理解事件的内容：写入时把图片换成引用、读回时换回来，都由写这些事件的 Host 做（见 agent-host 的[提及文件和附件](agent-host.md#提及文件和附件)），本包只提供按 SHA-256 存取大内容的接口。
- 存储格式不对外：CLI 的 JSON 事件流和 hooks 的输入都由 agent-host 定义，各有版本，存储格式迁移不会让用户的脚本和 hooks 失效；只用于实时显示的流式增量不存储。

## 会话的分支和回退

P3 交付。照 pi、Codex 和 Claude Code 共同的做法：

- **历史从不删除**：会话是一棵树，当前对话是从根到"当前位置"的一条路径。回退把当前位置移到某次用户输入之前，新的输入接在那里，被放弃的那一段仍然保留，可以再切回去（把当前位置移到它的末端，这时原来的那一段成为被放弃的）；分叉从来源 session 的当前位置或路径上某次用户输入之前开出一个新的 session，记下来源 session 和位置。
- **分支点是用户输入的边界**：每次用户输入有稳定的标识和自己的检查点，task 中途插入的 steering 也是，可以回退到它之前；只有正在运行的 task 不能作为分支点。
- **发给模型的只有这条路径上的历史**：路径上最近一次压缩之后的内容，加上新追加的内容；之前的内容没有改写，提示缓存和推理内容的校验都不受影响。被放弃的那一段不进入历史，也不生成摘要：摘要要多调用一次模型，而那一段留在记录里，随时可以切回去。
- **当前位置显式保存**，回退立即写入，否则在下一次输入前退出，回退就丢了。
- **设置**：模型和推理强度按路径上的记录；沙盒模式和审批策略保持当前的值，不因为回退到较早的位置而放宽，因为历史记录不能产生新的授权；和当前设置不同的部分作为追加的变更加在回退点之后。
- **文件和对话分开还原**：回退对话不改文件；文件按检查点还原，用户可以只还原对话、只还原代码或两者都还原。冲突检查沿用 agent-host 的[快照和撤销](agent-host.md#快照和撤销)。
- **回退之后要重新计算的状态**：文件读取的新鲜度记录、已加载的 skills。
- 用到的事件格式见[事件格式](#事件格式)。

## 分叉的存储

分叉引用父 session，不复制：只记录父 session 和截止的事件，之后只写自己的事件；大内容按内容哈希只存一份，记录引用它的 session；检查点的快照本来就在影子仓库里，分叉只为沿用的检查点建自己的引用，不复制任何文件内容。

- **读取**：run 的标识在整个库里不重复，分叉按路径读取时沿 `base` 走进父 session（以及父 session 的父 session）的 run，只读得到分叉位置之前、路径上的那一段。
- **大内容**：分叉时为路径上的事件引用的大内容建自己的引用。本包不理解事件的内容，按事件内容里出现的 SHA-256 摘要（64 位十六进制）找：摘要是内容的哈希，碰巧相同的字符串只会多留一份引用。按事件脱敏找"这个事件引用的大内容"用同一办法。
- **检查点**：分叉时把父 session 当时的整个检查点索引（包括不在路径上的检查点：它们改过的文件还在工作区里，撤销时要算进去）写进分叉自己的 `checkpoints.inherited` 事件，Host 为其中还有快照的检查点建分叉自己的引用。之后两边各记各的，互不影响。不在路径上的检查点在分叉里读不到它的输入事件，只用来还原代码。检查点在不在当前路径上，读取时按当前位置判断，只有路径上的可以作为回退的目标。
- 父 session 被删除或到期时，先在同一个事务里把分叉仍引用的事件改记到分叉名下，再删除其余内容；大内容和快照的引用分叉时已经建好，不用转移。以这些事件为来源的记忆由 Host 协调 memory 一起改记来源。每个项目一个数据库文件，所以这能在一个事务里完成。
- **改记的规则**：只处理直接从被删 session 分出去的分叉，按分叉创建的先后逐个进行。每个分叉从分叉位置沿路径往根走，把仍属于被删 session 的事件改记到自己名下，遇到已经属于别的 session 的事件（更早处理的另一个分叉，或被删 session 自己的父 session）就停下，改为从那个 session 的那个位置分叉；一直走到根的不再有父 session。分叉的分叉不用动：它们经过自己的父 session 读到这些事件。
- 仍被分叉引用的 session 也可以删除：删除前告诉用户还有几个分叉包含这段内容，用户可以选择一起删除。拒绝删除会让彻底删除取决于用户先处理分叉。一起删除时，Host 先取得要删的全部 session 的写锁再动手，有一个正被 Host 打开着就一个也不删：不留下只删了一半的会话树；分叉按创建的先后倒着删，轮到一个 session 时从它分出去的都已经删掉，没有事件要改记。

## 回退时的后台命令

回退开始新的 run，但后台命令属于 session（见 agent-runtime 的[后台命令](agent-runtime.md#后台命令)）。回退到某个检查点时，结束在这个检查点之后启动的后台命令，保留之前启动的，按命令的启动事件在会话树里的位置判断。

- 之后启动的命令属于被放弃的分支，继续运行会把输出送进不认识它们的对话，还可能在还原代码后继续改文件；之前启动的命令（如开发服务器、监视进程）仍在保留的历史里，它们之后的输出照常送到当前分支。
- 待批准的请求一律取消：它们属于被中止的 run，新的 run 需要时重新请求。
- 只回退对话时也按同样的规则结束命令；同时还原代码时，先结束命令再还原，仍有保留的命令在运行时，还原前提示它们可能继续改动文件。

## 检查点的保留

每个 session 保留最近 100 个检查点的快照。

- 更早的检查点仍留在会话记录里，可以回退对话，但标为"快照已清理"，不能还原代码。检查点内按工具调用做的快照跟随所属检查点一起清理。
- 快照的保存期限跟随 session，不单独设置；检查点数量也不提供配置项。
- 每个检查点在影子仓库里各有一个引用，引用名是 `<session_id>/<输入事件的 event_id>`（Host 加上 `refs/ospreycode/` 的前缀）；检查点之间不串成一条提交链，删除旧检查点只要删掉它的引用；设 `core.logAllRefUpdates=false`，避免 reflog 留住对象。同一个检查点内的各次快照串成这个引用下的一条提交链，所以跟随引用一起清理。
- 超出数量的检查点在写入新的检查点事件时标记，规则只取决于事件的先后，重建索引得到同样的结果。
- 清理的分工：Host 的 `workspace/` 列出影子仓库里现有的引用，session-store 从中挑出不再被这个工作区的任何 session 引用的（检查点已清理，或 session 已删除），`workspace/` 在快照沙盒里删除这些引用并回收不再被引用的对象。这样不用另记一张待删除的清单，Host 中途退出也不会留下删不掉的引用。回收的做法和实测的耗时见 agent-host 的[快照和撤销](agent-host.md#快照和撤销)：一次要 1 到十几秒，所以 session 运行中每超出 20 个检查点才清理一次，标记为已清理的检查点在那之前还占着磁盘。
